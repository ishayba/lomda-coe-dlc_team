## 1. מה יש בחבילה

הלומדה היא **קובץ HTML בודד**. כל הקוד, העיצוב והתוכן נמצאים בתוכו. אין קובצי JavaScript, CSS או תמונות נפרדים, ואין שרת או מסד נתונים.

| קובץ | תפקיד |
|---|---|
| `index.html` (או `aidlc-lomda.html`) | הלומדה עצמה |
| `README.md` | המסמך הזה |

**תלות חיצונית אחת, לא חובה:** הגופנים Rubik ו-IBM Plex Mono נטענים מ-Google Fonts. ברשת סגורה הלומדה עובדת כרגיל עם גופני המערכת (Arial וכדומה). ראו סעיף 6.

**איפה נשמרים הנתונים:** ההתקדמות, התשובות והסימונים של כל משתמש נשמרים רק בדפדפן שלו (localStorage). שום מידע לא נשלח לשרת.

---

## 2. לפני ההתקנה: התאמה לארגון

פתחו את הקובץ בעורך טקסט (VS Code, Notepad++ וכדומה) וחפשו `const CONFIG`. עדכנו את הערכים:

```js
const CONFIG = {
  org: 'יחידת ה-CoE AI-DLC הארגונית',          // שם היחידה בראש הדף ובתעודה
  course: 'לומדת AI-DLC: מעבר לרמות 3 ו-4',      // שם הלומדה
  contact: 'coe-aidlc@your-org.example',         // מייל ה-CoE להגשות ולקחים
  rulesRepo: 'git.your-org.example/coe/aidlc-rules', // ריפו הכללים הארגוני
  version: 'גרסה 1.0 · אוקטובר 2026',            // מוצג בתחתית תפריט הצד
  storageKey: 'aidlc-lomda-v1'                   // מפתח השמירה בדפדפן
};
```

> **שימו לב ל-`storageKey`:** שינוי שלו מאפס את ההתקדמות של כל המשתמשים. משנים אותו רק כשהתוכן השתנה מהותית ורוצים שכולם יתחילו מחדש.

שמרו את הקובץ בקידוד **UTF-8**, אחרת העברית תוצג כג'יבריש.

## 3. אפשרות א': שימוש מקומי בלי שרת

מתאים לבדיקה, להדגמה או למשתמש בודד.

1. העתיקו את הקובץ לתיקייה, למשל `C:\AI-DLC\lomda\`.
2. לחצו עליו פעמיים. הוא ייפתח בדפדפן ברירת המחדל.

ב-Chrome וב-Edge ההתקדמות נשמרת גם כשהקובץ נפתח מהדיסק. אם מעבירים את הקובץ לתיקייה אחרת, ההתקדמות לא עוברת איתו.

---

## 4. אפשרות ב': אתר פנימי על IIS (מומלץ)

כך כל העובדים ניגשים לאותה כתובת, וההתקדמות נשמרת לכל אחד בדפדפן שלו.

1. צרו תיקייה בשרת, למשל `C:\inetpub\wwwroot\aidlc-lomda\`.
2. העתיקו אליה את הקובץ ושנו את שמו ל-`index.html`.
3. ב-IIS Manager: **Sites** ← **Add Website** (או **Add Application** תחת אתר קיים).
   - **Physical path:** התיקייה מסעיף 1.
   - **Binding:** הכתובת הפנימית, למשל `aidlc.your-org.local`.
4. ודאו ש-`index.html` מופיע ב-**Default Document**.
5. אם נדרשת הזדהות: **Authentication** ← הפעילו **Windows Authentication** ובטלו **Anonymous**.
6. גלשו לכתובת ובדקו לפי סעיף 7.

אין צורך ב-.NET, ב-Node או במודולים נוספים. IIS מגיש את הקובץ כקובץ סטטי.

## 5. אפשרויות נוספות

| סביבה | איך |
|---|---|
| **Nginx / Apache** | מעתיקים את `index.html` לתיקיית ה-root של אתר סטטי. |
| **GitLab Pages / GitHub Pages פנימי** | מכניסים את `index.html` לריפו ומפעילים Pages. כך כל עדכון של ה-CoE עובר ב-Merge Request. |
| **S3 + CloudFront (AWS)** | מעלים ל-bucket עם הגדרת static website, ומגבילים גישה לרשת הארגון. |
| **SharePoint** | **לא מומלץ.** SharePoint Online חוסם הרצת קובצי HTML ומוריד אותם במקום להציג. |

## 6. רשת סגורה (בלי גישה לאינטרנט)

הלומדה עובדת גם בלי אינטרנט. רק הגופנים יוחלפו בגופני מערכת.

כדי לשמור על הגופנים ברשת סגורה:

1. הורידו מ-Google Fonts את Rubik ואת IBM Plex Mono בפורמט `woff2`.
2. שימו אותם בתיקייה `fonts/` ליד `index.html`.
3. בקובץ, החליפו את שתי שורות ה-`<link>` של `fonts.googleapis.com` בבלוק:

```css
@font-face{font-family:'Rubik';src:url('fonts/Rubik.woff2') format('woff2');font-weight:400 700}
@font-face{font-family:'IBM Plex Mono';src:url('fonts/IBMPlexMono.woff2') format('woff2')}
```

במקרה הזה החבילה כבר אינה קובץ בודד: `index.html` + תיקיית `fonts/`.

## 8. עדכון תוכן

כל התוכן נמצא בקובץ, במקטע `נתוני תוכן`:

| מה מעדכנים | איפה בקוד |
|---|---|
| פאזות | `PHASES` |
| פרופילים | `PROFILES` |
| סוכנים | `AGENTS` |
| פרסונות, משימות רמה 3 ו-4, תרגילים ושאלות | `PERSONAS` |
| שאלות בפרקים 1 ו-2 | `QUIZ` |
| טקסט השלבים | `CHAPTERS` |

אחרי כל עדכון: מעלים את `version` ב-`CONFIG`, ומעדכנים את הגרסה בראש המסמך הזה.

**מקור התוכן:** הריפו [awslabs/aidlc-workflows](https://github.com/awslabs/aidlc-workflows) ו[תיעוד ה-Workflow Profiles](https://awslabs.github.io/aidlc-workflows/guide/workflow-profiles/). לפני כל עדכון כדאי לוודא שמספרי השלבים והפרופילים עדיין תואמים לגרסה הנעולה בארגון.
